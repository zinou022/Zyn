1. The project in brief

The BUTEC HSE Integrated Platform is one web platform that brings the company’s HSE work into a single place. It has a Portal, which is the entry door, and a set of applications behind it. Each application covers one HSE process from start to finish.

Where the idea comes from

HSE information at BUTEC lived in many separate places: monthly statistics in Excel files, KPI and audit checklists in PDF, investigation reports and witness statements in Word, observations and worker documents in other files and emails. Every project reported in its own way. Follow-up depended on people chasing each other, and information was lost when a person moved or a project ended.

The platform was created to replace this with one controlled system: one login, one set of data, one way of working on every project.

What the Portal is

The Portal is the single front door. A user signs in once and sees only the projects and applications that match their role. The Portal also holds the project register, the user directory, announcements and notifications, and the platform backups. Applications do not keep their own users or projects; they all take them from the Portal.

6. Documents produced and saved

Every document the platform produces, or receives from a user, is saved by the system itself in a fixed folder structure. Nothing is filed by hand. Each document carries the project, the date, the author and a version number, and nothing is ever deleted: a correction becomes a new version and the earlier one stays (see Retention of information in Section 4).

6.1 How the folders are organised

The folders are split in two branches. The Corporate (E&C) branch is kept once for the whole company: it holds the standards every project uses, the platform records, and the results consolidated across projects and countries. The Project branch is repeated for every project: each project has its own complete set of folders, for example Project / PSM-13 / HSE Statistics Records / Monthly Statistics Reports / 2026-08. A file name states the project, the document and the period, for example PSM-13_Monthly-Statistics_2026-08_v2.

Within each branch, L1 folders group the documents of one area and L2 folders hold the documents themselves. Access follows the groups of Section 3 and is always limited by project and role. Access (R/W) lists who may create or change a document in its application. Access (R) lists who may only read it. Where the system writes a document by itself, nobody types it.

7. Quality requirements

  --------------------------------------------------------------------------------------------------------------------------------------------------------------
  Area                        Requirement
  --------------------------- ----------------------------------------------------------------------------------------------------------------------------------
  Security                    Access only through secure connections; passwords protected; every action limited by role and project.

  Availability and recovery   Automatic backups; a restore path that is tested before major changes.

  Ease of use                 The same look, wording and behaviour in every application; short, simple screens; works on desktop, tablet and phone.

  Cost                        Only free or open-source components, so the platform has no licence cost.

  Reproducibility             Data structure changes are versioned and the source is documented, so the platform can be rebuilt and maintained by someone new.
